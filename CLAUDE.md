# CLAUDE.md: правила работы над Task Tracker

## Кто пользователь
Руководитель ИИ-проектов, не программист. Пользуется трекером сам, для реальных задач.

## Как общаться
- Отвечать на русском, простыми словами, без жаргона. Если без термина не обойтись, объяснить его в одном предложении.
- После каждого изменения коротко рассказать: что сделано, как проверить (какие кнопки нажать), что дальше.
- Работать **по одному этапу** из плана. После этапа остановиться и ждать команды пользователя.
- Если задача неясна или противоречит SPEC.md, сначала спросить, потом делать.

## Главный документ
- `SPEC.md` — источник правды. Функции, поля и структура данных берутся оттуда.
- Не добавлять функции, которых нет в SPEC.md, без согласия пользователя. Если идея полезная, предложить её отдельно.
- Если пользователь согласовал изменение, сначала обновить SPEC.md, потом код.

## Технические границы (нельзя нарушать)
- Только `index.html`, `style.css`, `app.js` (и при необходимости ещё файлы .js без сборки).
- Чистый HTML, CSS, JavaScript. **Нельзя**: React, Vue, jQuery, TypeScript, npm, сборщики, CDN, внешние шрифты и библиотеки.
- **Нельзя**: базы данных, серверы, внешние API, аналитика, отправка данных куда-либо.
- Данные хранятся только в localStorage под ключом `taskTracker.v1`.
- Приложение должно работать при открытии `index.html` двойным щелчком (без локального сервера).

## Что нельзя менять без явного разрешения
- Ключ localStorage `taskTracker.v1` и структуру данных из SPEC.md (иначе пропадут сохранённые задачи). Если изменение необходимо, сначала написать код переноса старых данных и предупредить пользователя.
- Формат файла резервной копии: старые копии должны загружаться.
- Названия статусов и приоритетов.
- Нельзя удалять или перезаписывать данные пользователя без окна подтверждения.

## Стиль кода
- Понятные имена на английском (`addTask`, `renderBoard`), комментарии на русском там, где логика неочевидна.
- Небольшие функции, каждая делает одно дело.
- Весь ввод пользователя выводить как текст (`textContent`), не через `innerHTML`, чтобы избежать поломок и уязвимостей.
- Чтение localStorage оборачивать в `try/catch`: если данные повреждены, не падать, а показать сообщение.
- Цвета задавать CSS-переменными, чтобы работала тёмная тема.
- Вёрстка сначала под телефон (от 375px), затем под большие экраны.

## Проверка перед сдачей этапа
- Открыть `index.html` и убедиться, что в консоли браузера нет ошибок.
- Пройти соответствующие пункты «Критериев готовности» из SPEC.md.
- Честно сообщить, что проверено, а что нет.
